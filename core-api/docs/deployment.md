# Развёртывание Matchmaker

Локальный запуск и VPS — разные этапы. Публичный VPS не настроен: адрес сервера, SSH-доступ, домен и SMTP-учётные данные не предоставлены. Наличие Dockerfile не означает выполненный деплой.

## Подготовка сервера

На Linux-сервере нужны Docker Engine, Compose plugin, DNS-запись домена и HTTPS reverse proxy (например, Caddy). Скопируйте репозиторий и настройте корневой `.env`. Используйте отдельные случайные JWT_SECRET и POSTGRES_PASSWORD. Введите SMTP-настройки в окружение API и установите ENVIRONMENT=production, CORS_ORIGINS на точные адреса клиентов.

Compose в репозитории — демонстрационное окружение: Mailpit не отправляет внешние письма. Для VPS уберите Mailpit и направьте API на ваш SMTP. Порты PostgreSQL/Redis не публикуйте. Порт API остаётся привязан к loopback, reverse proxy публикует HTTPS. При нескольких API-процессах Redis должен быть общим. Миграции выполняет один процесс до запуска остальных реплик.

## Последовательность

1. Получить исходники и заполнить переменные.
2. Запустить `docker compose up --build -d`.
3. Проверить `docker compose ps`, `/health` и доступность `/docs`.
4. Настроить HTTPS и корректные trusted proxy IP в Uvicorn для лимитов по клиентскому IP.
5. Пройти регистрацию с настоящей почтой и убедиться в приходе письма.
6. Проверить веб- и мобильный клиенты, CORS и запрет доступа к чужому match.
7. Настроить регулярный pg_dump, проверить восстановление копии на отдельной базе.
8. Передать комиссии URL и инструкцию демонстрации, не включающую административные секреты.

У этого проекта нет доступа к реальному VPS в текущей сессии. Фактическую публикацию и её проверку нельзя отметить завершёнными до выполнения этих действий.
