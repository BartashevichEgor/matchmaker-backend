# Контракт авторизации по прототипу Figma

Дата сверки: 16 октября 2026. Основание: экраны загрузки, входа, регистрации, подтверждения email и ошибочных состояний для mobile, tablet и desktop.

## Что обязуется делать backend

| Экран | Действие клиента | Метод API | Результат |
|---|---|---|---|
| Loading | Проверить доступность сервера | `GET /health` | `200` означает, что можно показать форму; сетевой сбой показывает «Нет подключения» и кнопку повтора |
| Вход | Email и пароль | `POST /api/v1/auth/login` | `200` с JWT; `401` — неверная пара; `403` — сначала подтвердить email |
| Регистрация | username, email, пароль, повтор пароля | `POST /api/v1/auth/register` | `201`, затем показать экран кода; `409` при занятом email/username; `422` при неверном поле |
| Подтверждение email | Email и код из шести цифр | `POST /api/v1/auth/verify-email` | `200`, затем вернуть пользователя на вход |
| Повтор кода | Email | `POST /api/v1/auth/resend-verification` | Нейтральный ответ, чтобы не раскрывать существование аккаунта |
| Забыли пароль | Email | `POST /api/v1/auth/forgot-password` | Нейтральный ответ; затем экран нового пароля |
| Новый пароль | Email, код, новый пароль и повтор | `POST /api/v1/auth/reset-password` | `200`, старые сессии отзываются |

## Поля и валидация

- `username`: 3–30 символов, `a-z`, `0-9`, `.`, `_`, `-`; сервер переводит к нижнему регистру и проверяет уникальность.
- `email`: валидный e-mail; сервер приводит к нижнему регистру.
- `password`: от 10 до 128 символов. Это правило должно быть одинаковым в KMP и React, хотя ранняя KMP-версия проверяла только 6 символов.
- `password_confirm`: должен совпадать с `password`. Это можно проверить до запроса и повторно проверяет сервер.
- `code`: ровно шесть цифр; действует 10 минут, максимум 5 неверных попыток.

## Привязка состояний формы

Клиент показывает ошибку у поля по `422.detail[].loc` и использует HTTP-статус для общего состояния. Тексты ошибок являются ответственностью клиента и должны быть одинаковыми в React и iOS:

| Условие | Статус | Текст интерфейса |
|---|---:|---|
| Неверный email | 422 | «Введите корректный e-mail» |
| Пароль слишком короткий | 422 | «Пароль должен содержать не менее 10 символов» |
| Пароли отличаются | 422 | «Пароли не совпадают» |
| Username занят | 409 | «Это имя пользователя уже занято» |
| Email занят | 409 | «Этот e-mail уже зарегистрирован» |
| Неверный пароль | 401 | «Неверный e-mail или пароль» |
| Email не подтверждён | 403 | «Подтвердите e-mail кодом из письма» |
| Нет ответа сети | нет HTTP-ответа | «Нет подключения. Проверьте интернет и повторите попытку» |

Не отправляйте пароль, токены или полный ответ сервера в логи клиента. После логина access token передаётся в `Authorization: Bearer <token>`; refresh token используется только в `/auth/refresh` и заменяется после каждого успешного обновления.
