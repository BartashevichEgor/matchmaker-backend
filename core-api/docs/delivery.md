# Материалы по backend для сдачи

Дата подготовки: 6 октября 2026 года. Исполнитель направления: Егор Барташевич. Это описание текущей реализации; дата готовности не переносится задним числом на сентябрьские дедлайны.

## Отчёт 2/3 Проектирование схемы базы данных

Цель: хранить пользователей, анкеты, компетенции и проекты, обеспечивать взаимный выбор и доступ к коммуникации. Выбран PostgreSQL, реализованы SQLAlchemy-модели и Alembic-миграция. Присланная схема из четырёх таблиц сохранена и расширена под требования проекта. Полная ER-диаграмма, словарь полей, ключи и правила целостности приведены в [database.md](database.md). Миграция находится в `migrations/versions/0e5a5b1319e6_initial_matchmaker_schema.py`.

Критерии приёмки: создание схемы на пустой БД; одна анкета на пользователя; уникальные связи навыков; корректные диапазоны level/weight; запрет дублирования match. Тесты проверяют API-сценарии на изолированных БД; результаты последнего запуска следует прикладывать вместе с версией кода.

## Отчёт 2/4 Проектирование API и документация запуска

Выбран REST/JSON, версия `/api/v1`, типизированные входы и ответы Pydantic. Реализованы системные методы, авторизация, профили, справочники, проекты, рекомендации и matches. [api.md](api.md) описывает доступы, примеры, ошибки и контракт Node.js-чата; `/openapi.json` отражает реализованные маршруты.

README содержит окружение, локальный и Docker-запуск, миграции, тесты и переменные. Корневой `.gitignore` исключает окружения, секреты, локальные письма и данные БД. Примеры `.env.example` не содержат рабочих ключей. Swagger получает JS/CSS из локального пакета.

## Что осталось в командной части

Рома реализует React-клиент и WebSocket-чат; текущая HTML-страница служит демонстрацией и не заменяет его полноценный клиент. Алина подключает iOS-клиент. Вероника согласует требования, макеты и итоговое оформление. По документу требований добавлены admin-модерация, справочник ролей и GitHub-поле анкеты; повторяющиеся US-a идентификаторы в разных ролях нужно исправить в исходном документе.

Схема и API описывают новые технические решения: match относится к паре «кандидат — проект», вступление отдельно подтверждает кандидат, полномочия владельца определяются owner_id. Эти решения следует согласовать с командой при интеграции. Косинусный score рассчитывается в Python по данным PostgreSQL; граф связанных навыков и Redis-кэш сессий пока не реализованы.
