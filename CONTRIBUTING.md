# Правила совместной разработки Matchmaker

## Ветки и задачи

- `main` — только проверяемые интеграционные изменения;
- `feat/<номер>-краткое-название` — новая функциональность;
- `fix/<номер>-краткое-название` — исправление дефекта;
- `release/0.N` — подготовка учебного релиза.

Каждая карточка Jira содержит исполнителя, оценку в Story Points, критерии готовности и ссылку на PR. Статусы: **Product Backlog → Sprint Backlog → In Progress → Sprint Done**. В `Sprint Done` попадает только задача с проверкой и фактическим временем.

## Коммиты и pull request

Используйте понятный заголовок: `feat(api): добавить список навыков`, `fix(web): обработать пустой каталог`, `docs: обновить инструкцию запуска`. Один PR решает одну связанную задачу. Перед слиянием автор описывает проверку, а один участник команды выполняет review.

## Роли и review

| Область | Владелец | Reviewer по умолчанию |
| --- | --- | --- |
| FastAPI, БД, OpenAPI, deployment | Егор | Роман или Алина |
| Web React/TypeScript | Роман | Егор или Алина |
| KMP/iOS, клиентские модели и QA | Алина | Егор или Роман |
| Figma, UX-тексты и UI-состояния | Вероника | Роман и автор затронутого клиента |
| Архитектурная документация | автор решения | один участник, не являющийся автором |

Роль означает ответственность за область, а не автоматическое авторство всех
изменений в ней. В описании PR указываются Jira-ключ, команда проверки,
изменение OpenAPI (если есть) и имя фактического reviewer. Нельзя добавлять
review задним числом без ссылки на PR/комментарий.

## Definition of Done

1. Код соответствует контракту API и не содержит секретов.
2. Добавлены или обновлены тесты; `pytest`/`npm test` и сборка проходят.
3. Ошибки отображаются безопасно: без токенов, паролей и stack trace.
4. Обновлены README, OpenAPI или документы, если затронуты контракт, запуск либо архитектура.
5. Карточка Jira содержит фактическое время и ссылку на PR/демонстрацию.

## Релиз

Из `release/0.N` проводится итоговая проверка, обновляется `CHANGELOG.md`, создаётся тег вида `v0.N.0`, затем изменения попадают в `main`. Откат — возврат к предыдущему тегу после фиксации причины в Jira.
