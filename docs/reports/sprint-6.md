## 6/1. Логирование и модульное тестирование на клиенте

Web-проект содержит тесты и сборку; в финальном ответе прикладываются выводы
`npm test` и `npm run build`. Ошибки API должны логироваться без токенов и
персональных данных. Не заявляйте число тестов вручную: берите его из вывода
последнего запуска CI/терминала.

## 6/2. Базовый функционал приложения

Реализованный сквозной сценарий: health → регистрация → локальное письмо с
кодом → подтверждение e-mail → login/JWT → профиль/навыки → каталог проектов.
Для демонстрации нужны два терминала (API и Vite) и один браузер; детальный
порядок запуска есть в [`docs/deployment.md`](../deployment.md).

## 6/3. Подтверждение e-mail и аватар

Подтверждение e-mail реализовано: код формируется локальным mail outbox,
затем применяется endpoint подтверждения, после чего доступен login. UI может
показывать инициалы пользователя как avatar fallback. **Загрузка изображения
аватара не реализована**: нет backend upload endpoint/хранилища/валидации
файла. Это переносится в следующую карточку, а не отмечается как готовое.

## 6/4. Личные сообщения — часть 2

Backend-часть закрыта в `chat-service`: модель `conversation`/`message`,
авторизация только участников match, persistence, REST-history, WebSocket,

закрытия клиентской задачи остаётся UI-интеграция web/KMP и запуск этих
интеграционных тестов с PostgreSQL.
