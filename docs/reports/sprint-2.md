## 2/S3. Scrum meeting 04 — неделя 4

Команда зафиксировала единый путь: регистрация → код e-mail → подтверждение
→ login → JWT. Для полей согласованы правила: `username` 1–50 символов,
пароль 8–128 символов, code из шести цифр. Принято решение не дублировать
валидацию интерфейса на каждом клиенте, а держать серверный контракт
источником истины.

На следующую неделю: Рома завершает responsive web-экраны, Алина — KMP
контракт/тесты, Вероника — дизайн ошибок, Егор — FastAPI, миграции и Swagger.

спринта.

## 2/1. Use Case и сценарии

Use Case-диаграмма находится в
[`core-api/docs/use-case-diagram.drawio`](../../core-api/docs/use-case-diagram.drawio),
PNG — в [`core-api/docs/use-case-diagram.png`](../../core-api/docs/use-case-diagram.png).
Основные акторы: гость, подтверждённый пользователь, владелец проекта и
администратор. Основные сценарии: регистрация, подтверждение e-mail, вход,
редактирование профиля, выбор навыков, создание проекта, взаимный swipe,
match и присоединение к проекту.

## 2/2. Проектирование UI

Прототип: [Figma Matchmaker](https://www.figma.com/design/PQ2HmEr99bpWbDCxgcnMbe/Project-Matchmaker?node-id=0-1).
Вероника подготовила состояния auth, ошибок, профиля и каталога для mobile,
tablet и desktop. Эти состояния использованы как источник требований для
web и KMP.

## 2/3. Схема БД

Выбрана PostgreSQL; SQLite применяется только для быстрых локальных проверок
и pytest. Схема и правила миграций описаны в
[`docs/database.md`](../database.md), исходник ER —
[`docs/uml/schema.puml`](../uml/schema.puml). Реализация находится в
`core-api/app/models.py` и Alembic-миграциях.

## 2/4. API, README и .gitignore

API использует JSON и префикс `/api/v1`; интерактивная спецификация —
`/docs`, машинная — `/openapi.json`, версионируемая копия —
[`api/openapi.yaml`](../../api/openapi.yaml). README описывает запуск,
технологии и окружение; `.gitignore` исключает секреты, `.env`, базы,
логи и зависимости.
