# ADR-0002: Модульный монолит для backend

**Статус:** принято. **Решение:** один FastAPI-процесс с модулями `auth`, `profiles`, `catalogs`, `projects`, `recommendations`, `swipes`; в Phase 4 чат планируется как отдельный сервис из-за постоянно открытых соединений.

**Почему не микросервисы:** команда небольшая, доменная модель общая, а отдельные сервисы добавили бы сетевые тайм-ауты, распределённые транзакции, дублирование авторизации и стоимость развёртывания. Модульные границы уже позволяют выделять сервисы позже.

**Отказы и повторы:** транзакции БД и уникальные ограничения защищают от дублирования мэтчей; API возвращает предсказуемые 4xx/5xx. После реализации Phase 4 чат должен повторно проверять JWT и доступ к комнате через core API; при недоступности API соединение не допускается.

**Пересмотр:** выделять рекомендации, уведомления либо чат в независимые сервисы только при измеримой нагрузке, независимом релизном цикле или необходимости очереди сообщений.
